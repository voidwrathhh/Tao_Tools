### 2.2 crates.io 路线已被否决（记录备查）

曾考虑「只复制 Director 源码，框架用 crates.io 依赖」，实测不可行：

| crate | crates.io 状态 |
|---|---|
| `makepad-director` / `makepad-screen` / `makepad-wm-theme` / `makepad-code-arch` / `makepad-diskmap` | ❌ **均未发布** |
| `makepad-widgets` / `makepad-draw` / `makepad-platform` / `makepad-code-editor` | ⚠️ 已发布但是 **1.0.0**，仓库是 **2.0.0**（大版本落后，API 不兼容） |

> 结论：Director 的 14 个直接依赖里有 5 个无法从 crates.io 获取，且已发布框架落后一个大版本。**不存在「不搬框架」的捷径。**

### 2.3 附带成果：代码面板中文渲染缺陷（✅ 已修复并验证）

代码编辑器内中文显示为豆腐块，日志 `font miss U+FF0C role=custom set=International tried=[liberation_mono]`。

**完整定位过程与最终修复见 §9。** 结论：不是策略链的问题，也不是主题文件的问题 —— 是 `install_theme_fonts()` 用 `policy.monospace`（International 下只有 `[LIBERATION_MONO]` 一个 face）重建代码样式字体，且桌面端没有任何 CJK 回退机制。修复为给代码样式启用独立的 `CODE_CHAIN`（打包等宽字体 + 宿主黑体）。

**验证**：`font miss` 从 3 条降至 **0 条**，`cargo build` 零告警，`cargo test -p makepad-platform --lib font_policy` → **9 passed**。

## 9. 字体方案（✅ 已决策、已实施、已验证）

### 9.1 决策

**只用系统黑体**（`C:/Windows/Fonts/simhei.ttf`），不保留 LXGW 兜底。

### 9.2 最终修复（3 处改动）

| 文件 | 改动 |
|---|---|
| `platform/src/font_policy.rs` | 新增 `SYSTEM_CJK_FONT_ASSET`（绝对路径常量）与 `CODE_CHAIN`（=`[LIBERATION_MONO, SYSTEM_CJK_FONT_ASSET]`） |
| `widgets/src/font_policy.rs` | `install_theme_fonts()` 里代码样式的字体域从 `policy.monospace` 换成 `CODE_CHAIN`；另加 `register_font_member_path()` + `is_absolute_font_path()` 做绝对路径分派 |
| `platform/src/script/res.rs` | 抽出 `register_abs_resource_path()`，`res.file` 脚本 API 与字体链共用一份实现 |

**关键设计**：`CODE_CHAIN` **刻意独立于 `policy.monospace`**。后者被 `assets` 与字体清单镜像，而清单描述打包发运内容 —— 宿主字体按定义不发运，无法加入。用独立链后**完全不触碰任何清单不变量**。

### 9.3 定位过程（4 个假设被逐一实测证伪）

| 假设 | 证伪依据 |
|---|---|
| 改 `policy.monospace`（International 专属链） | 代码样式不走策略链。且不变量要求 `assets` == 各 role 链精确并集，塞入宿主路径语义错误 |
| 改 `append_style_fallbacks()` 加 `font_code` | 该函数被 `style.mobile()` 门控（`widgets/src/desktop_style.rs:243-248`），**桌面端从不调用** |
| 改 `theme_desktop_dark.rs` 的 `font_code` | Windows 皮肤是 `mod.theme = mod.themes.light`（`widgets/themes/windows/theme.splash:1`） |
| 改 `theme_desktop_light.rs` / `_skeleton.rs` 的 `font_code` | 已改并加 `cjk` 成员，但移除探针混淆后 `member=cjk` 不再加载 —— 说明 **`install_theme_fonts()` 在最后覆盖了主题文件里的 `font_code`** |

**真正的机制**：`widgets/src/lib.rs:312` 调用 `install_theme_fonts()`，它用 `family_value(vm, policy.monospace, ...)` 重建 `mod.themes.*.font_code`。International 的 `policy.monospace` = `MONOSPACE = [LIBERATION_MONO]` —— **恰好一个 face**，与日志 `tried=[liberation_mono]` 完全吻合，也解释了主题文件改动为何被清掉。

### 9.4 ✅ 验证证据

最小复现探针 `apps/codeedit`（三个 Label：`theme.font_regular` / `theme.font_code` ×2），`MAKEPAD_TRACE_FONT_LOAD=1`：

```
修复前：font miss U+FF0C role=custom set=International tried=[liberation_mono]
        font miss U+FF08 ... / font miss U+FF09 ...        （3 条缺失）

修复后：font load: member=system_cjk path=C:/Windows/Fonts/simhei.ttf bytes=9745792
        font miss: (无缺失 ✓)                               （0 条缺失）
```

成员名 `system_cjk` 是 `SYSTEM_CJK_FONT_ASSET.id`（非探针自定义名），确证加载来自 `CODE_CHAIN`。

**其它验证**：
- `cargo test -p makepad-platform --lib font_policy` → **9 passed; 0 failed**（含 `assets_are_the_exact_unique_union_of_role_chains`）
- `cargo check -p makepad-widgets` → 零 error 零 warning
- `cargo build -p makepad-codeedit --release` → 0 warning

> ⚠️ **日志陷阱**：缺失日志只出现全角标点 `，（）`，**不代表汉字正常** —— `shaper.rs:281-286` 对 CJK 区间（`LazyFontFamily::Cjk.contains(ch)`）的缺失**静默 return**，而 `U+FF0C/U+FF08/U+FF09` 属"半角及全角形式"区块、不在该分类内，所以只有它们被打印。判断修复是否生效**必须看这两个全角标点是否消失**。

### 9.5 代价与限制

| 项 | 内容 |
|---|---|
| 平台 | **Windows 专属**。非 Windows 主机上该路径不存在 → 记一条 missing-font 提示，代码样式里 CJK 显示为方框（不崩） |
| 体积 | **零增长**。字体不在仓库、不进二进制、不进 wasm 载荷（运行时从磁盘读，无 `include_bytes!`） |
| 回退 | **无兜底**（按决策）。机器缺 `simhei.ttf` 时中文不显示 |
| 可移植性 | 路径硬编码在 `SYSTEM_CJK_FONT_ASSET` 一处，改字体只需改这一个常量 |

> 附注：`widgets/fonts/` 与 `widgets/resources/` 存了两份 LXGW 副本（各 19MB），manifest 只引用 `resources/` 那份。
