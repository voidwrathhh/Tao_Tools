# toolhub 开发计划

> 状态：进行中　最后更新：2026-11-22　版本基线：v1.2.0

## 1. 目标

工具中心入口与注册表：列表展示已注册工具、启动、直达各工具设置、排序过滤。`registry.json` 是唯一数据源。

## 2. 非目标与分工边界

- **不代管各工具的业务设置**：只提供 `settings` 直达入口，具体设置界面属于各工具。
- **不静默写注册表**：自动发现未注册工具只做提示，补登记仍由人确认（注册表是约定，不能被自动改写）。
- 不做插件/脚本市场之类的扩展体系。
- 进程管理只负责"自己拉起的实例"（记录 pid、结束该 pid），不按名字杀进程，不接管各工具自身单例逻辑。

## 3. 候选功能

### P2 收藏 / 置顶分组

- 验收：可置顶/分组，显示在列表顶部；状态写本地 `~/.tao_tools/toolhub/config.json`，不改 `registry.json`。

### P2 启动参数模板

- 验收：同一工具可保存多套启动参数，启动时选择；只存本地配置。
- 与 [copilotkey](copilotkey.md) 的「多套配置切换」区分：那边切键位配置，这边切命令行参数。

## 5. 风险与未决问题

- `cargo metadata --no-deps` 在 GUI 启动时于后台线程跑一次（配合前端每帧轮询结果），工作区很大时仍有 1–2 秒延迟；目前不做磁盘级缓存，失败时降级为一条提示，不影响启动。
- 自动发现要求 `cargo` 在 PATH 中，`cargo install` 后离开仓库的场景会失效，现已降级为「仅提示不可用」。
- 收藏与排序（现有 `order`）语义要合并清楚，避免两套顺序机制冲突。
- 过滤态下的「上移/下移」与绝对下标错位：当前按全局下标交换，过滤后可见序列与全局顺序不一致；若真要做，按可见序列重排。
- v1.1.0 的两个默认取舍（待后续拍板）：
  - 解析结果缓存后，刚 `build` 完不点「刷新」会看到旧 exe 路径；目前接受，靠「刷新」或启动失败自动失效兜底。
  - 同一工具已在运行时只提示、不重复拉起（硬规则），暂未提供「允许 GUI 多开」开关。
- v1.2.0 的取舍：
  - 启动参数改为逐项 `Command::args` 后不再经 `cmd /K`，控制台工具退出时窗口随之关闭，不再保留现场（以参数绝对安全为先）。
  - 回退到 `cargo run` 启动时，「结束」只会结束 cargo 包装进程，其拉起的真实子进程可能残留；已 build/install 的工具不受影响。
