# 开发计划索引

本目录集中存放各工具的开发计划：**未完成功能、优先级、验收标准、分工边界**。

时态分工（避免同一件事写两处、必然漂移）：

| 位置 | 管什么 |
|---|---|
| `Tools/<工具>/README.md` | **现状**：版本、已完成能力、用法、环境依赖 |
| `plans/<工具>.md` | **未来**：待做功能、优先级、验收标准、边界、未决问题 |
| `项目日志.md`、`Tools/<工具>/项目日志.md` | **过去**：每次改动记录 |

## 规则

- 文件名与 `Tools/` 下工具目录名一致：`plans/<工具名>.md`；尚未落地的工具用拟用名，并在下表标「未注册」。
- **动手前先读**：改某个工具前，先读它的计划与本文索引。
- **计划先行**：新增功能先在计划里登记（含验收标准），再写代码。
- **完成即删**：功能完成后从计划删除，写进该工具 `项目日志.md`，README 功能列表打 `[x]`。
- **不改 README 抄计划**：README 的「开发进度 / 开发计划」只写 ≤3 行摘要 + 本计划链接。
- 计划章节固定：目标 / 非目标与分工边界 / 候选功能（含验收标准）/ 版本规划 / 风险与未决问题。
- 登记新功能前先 `grep` 本目录，确认不与其它工具重复；重叠时在「分工边界」写明谁做、谁不做。
