# blueinfo 开发计划

> 状态：进行中　最后更新：2026-11-22　版本基线：v1.1.0

## 1. 目标

桌面蓝牙调试与数据可视化：串口蓝牙（HC05/HC06）通信、实时曲线、参数下发、日志导出，带独立设置窗口供 toolhub 直达。

## 2. 非目标与分工边界

- **TUI 串口终端不做** → 归 [sertool](sertool.md)。
- **通用串口调试（无图形）不做**：本工具一切功能围绕图形界面与可视化。
- **不做跨工具共享代码**：与 sertool 的「串口参数配置」各自实现，字段与取值对齐 sertool 定下的模型（见 P2）。
- 不做 BLE 之外的无线协议（WiFi/MQTT 等）本阶段不立项。

## 3. 候选功能

### P0 断线重连失效（一次失败即永久放弃）· 本轮执行

- 证据：`src/gui.rs:320-345` 的重连失败分支 `self.comm = None`（`gui.rs:338`），而重连准入条件是 `self.comm.is_some() && !is_connected()`（`gui.rs:322-324`）→ 置 None 后永不重试，与 README「断线自动重连（3 秒周期）」矛盾；`gui.rs:135` 的首次连接会清曲线，重连路径不清，时间轴会断裂。
- 做法：把连接态与 `Option<CommState>` 拆开，用 `attempts`/`next_retry_at` 独立驱动重试，失败只记日志不丢端口信息；成功时统一重置 `plot_time_start`；「断开」按钮置显式关闭标志，杜绝自动重连。
- 验收：拔线后 30s 内每 ~3s 一条「[重连] 尝试…」，插回自动恢复且曲线继续追加；点「断开」后不再重试；重连后时间轴连续（不清空）。
- 版本：patch（v1.1.1）
- 待决：固定 3s 还是指数退避（建议 1/2/4/8s 封顶 10s）。

### P0 文本→曲线：伪造时间轴 + 回显污染通道 · 本轮执行

- 证据：`gui.rs:359-364` 用 `len() as f64 * 0.01` 当时间戳（假设 100Hz 定采样），10Hz 设备 x 轴被压缩 10 倍，还与二进制真实时间 `pkt.timestamp - plot_time_start`（`gui.rs:389`）混在同一坐标系；`comm.rs:119` 把 `>>> {text}` 写进同一个 `text_lines`，`gui.rs:358` 对每行无条件 `parse_text_value` → 回显的 `SET_L_TARGET: 500` 会新建同名曲线。
- 做法：连接时记 `Instant` 作原点，文本与二进制共用单调 `rel_time`；日志行加类别（Rx/Tx/Err），只对 Rx 且非 `>>>`/`[..]` 前缀做解析；`latest_raw` 改按通道序输出，别用 HashMap 迭代序。
- 验收：10Hz 发 10 次 `CH1: 1`，曲线 x 跨度 ≈1.0s±0.1s；下发参数后通道数不变；文本与二进制混发时时间轴一致。
- 版本：patch（v1.1.1）
- 待决：设备时间戳若可回绕，是否改单调计数。

### P1 读写线程分离（读线程持锁拖慢发送/断开）

- 证据：`comm.rs:202-218` 在 `port.lock()` 内做 `p.read()`（50ms 超时），而 UI 线程 `send_text`（`comm.rs:109`）、`send_params`（`comm.rs:129`）、`disconnect`（`comm.rs:96`）、`Drop`（`comm.rs:177`）抢同一把锁；且全是 `lock().unwrap()`，poison 即 panic。
- 做法：读线程独占读句柄，写侧改 mpsc（UI 投递，读线程 select 后写出）；短期内先把 `unwrap` 换成 `unwrap_or_else(|e| e.into_inner())`，并把日志回显移到锁外。
- 验收：持续读时点「发送」「断开」返回 <30ms（`Instant` 打点可验），UI 不掉帧；100 次连发无 panic。
- 版本：minor

### P1 协议契约与帧解析加固

- 证据：`README.md:96` 的 C 示例写 `pkt.length = 12 + count * 8`，而 bincode 1 定长编码实际是 f64(8)+u8(1)+Vec 的 u64 前缀(8)+8n = 17+8n，照 README 发的帧必然解析失败；`README.md:89` 的 XOR checksum 在 `comm.rs:289` 从未校验；`comm.rs:281-286` 直接信任 `payload_len`，坏帧可让累积缓冲涨到 OOM 且无重同步。
- 做法：按实际布局重写 README C 示例（含 u64 前缀）；`payload_len` 加上限（≤64KB）与超时丢弃；bincode 失败时逐字节滑窗重找魔数。
- 验收：用修正后的 C 示例发 1 帧，Rust 端逐值一致；注入 `length=0x7FFF_FFFF` 坏帧后内存不涨、500ms 内回文本模式；截断/乱序流后能重新同步。
- 版本：minor（文档修正可单独 patch）
- 待决：加 CRC 属改协议，要设备端同步；是否改用 README:88 的定长 `channels[8]` 取消 Vec 前缀。

### P1 主界面补交互（快捷指令条 + 通道显隐）

- 证据：`gui.rs:498` 提示「每行一条，显示在左侧指令面板」，但 `custom_commands` 从未渲染（`left_panel` `gui.rs:535-768` 不含它）；`PlotChannel.visible`（`data_struct.rs:124`）只在 `gui.rs:786` 被读，无 UI 可改；`gui.rs:537` 与 `gui.rs:590` 两个 CollapsingHeader 同名「蓝牙设备」，egui 按文本生成 id 会串折叠状态。
- 做法：按 `custom_commands` 渲染按钮（点击即 `send_text`）；绘图区加通道列表，复选框绑 `visible`、双击改名（仅前端显示）；第二个折叠标题改「参数调试」并加 `id_salt`。
- 验收：设置里加一条指令保存后主界面出现按钮，点击后日志出现 `>>> 指令`；取消勾选任一通道其曲线消失且重启保持；两个面板可独立展开。
- 版本：minor

### P2 BLE 低功耗蓝牙拓展（btleplug）

- 验收：新增「BLE 模式」与串口模式并列；能扫描、连接、浏览 GATT 服务/特征、订阅通知；通知数据进曲线与日志；断开可重连。
- 备注：接口按 `comm.rs` 思路抽象（独立线程 + channel 交给 GUI），GUI 循环不得阻塞在 BLE 调用上。

### P2 截图保存

- 验收：曲线区可保存 PNG 到 `~/.tao_tools/blueinfo/`，文件名带时间；只含绘图区。`egui_plot` 无内建截图，需 viewport screenshot 后按 `plot_rect` 裁剪，验收写明「产物像素尺寸 = 绘图区尺寸」。

### P2 串口参数配置（数据位 / 停止位 / 校验位）

- 验收：设置窗口与连接面板可选数据位/停止位/校验位，连接时生效。
- **与 sertool 同源**：字段名与取值对齐 sertool 已落地模型；不共享代码（除非用户同意抽 crate）。

### P2 多语言界面切换

- 验收：中/英切换存配置，重启生效；至少覆盖菜单与设置项。

### P2 历史配置导入导出（跨设备）

- 验收：配置可导出 JSON 并导入，导入前校验版本字段，失败给中文提示。

### P2 数据回放

- 验收：可加载已导出日志按时间轴回放到曲线区，支持暂停/快进。

## 5. 风险与未决问题

- `btleplug` 在 Windows 走 WinRT，需要对应 feature 与系统蓝牙权限；与 `serialport` 的线程/句柄模型不同，需独立线程与状态机。
- BLE 与串口双模式切换时，曲线数据源要能平滑切换，避免环形队列被两路数据混写。
- 串口参数配置依赖 sertool 先落地模型，顺序不能反。
- 协议加固会动到与设备端的契约，先只做「文档修正 + 长度上限 + 重同步」，加校验位/CRC 需设备端同批升级。
